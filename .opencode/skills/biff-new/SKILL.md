# Scaffold a Biff Project

Create a new [Biff](https://biffweb.com/) web application using the official starter command. The starter generates a minimal CRUD app that demonstrates most Biff features. See `CONVENTIONS.md` in the repo root for the argument grammar this skill follows.

## Arguments

| Input             | Target                                                                       |
|-------------------|------------------------------------------------------------------------------|
| `<project-name>`  | Required. The directory name for the new project (the official scaffolder prompts for the main namespace separately). |
| (no argument)     | Prompt the operator for a project name, main namespace, and project directory before running the scaffolder. |

This skill is exempt from the `all` and `<path>` rows of the standard scope vocabulary because scaffolding has no useful default scope. See `CONVENTIONS.md` for the standard.

## Mutation

Mutates by default: runs the official Biff scaffolder (`clj -M -e '(load-string (slurp "https://biffweb.com/new.clj"))'`), which is interactive and writes a complete starter project tree (see the `biff` skill's Project Layout section for what is written). After the scaffolder finishes, this skill runs `clj -M:dev dev` once to generate `config.env`, build the Tailwind CSS, and verify the app responds on `localhost:8080`. No `--report` flag; preview the side effects by reading this `SKILL.md` and the upstream `https://biffweb.com/new.clj` script.

## Prerequisites

Verify before proceeding. If anything is missing, stop and tell the user.

- Java 17 or higher: `java --version`
- Clojure CLI: `clj --version`
- Outbound network access to `biffweb.com` (the scaffolder loads from there)

## Steps

### 1. Resolve project name and namespace

Use `$ARGUMENTS` as the project name if provided. Otherwise ask the user for one.

The official scaffolder is interactive and prompts for:

- The main namespace (e.g., `com.example`)
- A directory name for the new project

Ask the user for both values up front and confirm them before running the command.

### 2. Run the starter

```bash
clj -M -e '(load-string (slurp "https://biffweb.com/new.clj"))'
```

In some versions of PowerShell, the inner double quotes must be doubled:

```powershell
clj -M -e '(load-string (slurp ""https://biffweb.com/new.clj""))'
```

The scaffolder writes a complete starter project tree (see the `biff` skill's Project Layout section).

### 3. Verify the project starts

```bash
cd <project-dir>
clj -M:dev dev
```

This generates `config.env` if missing, builds `target/resources/public/css/main.css`, watches files for live evaluation, and serves the app on `localhost:8080`.

Confirm the server responds:

```bash
curl -fsS http://localhost:8080/ -o /dev/null
```

If the curl exits non-zero, capture the dev log and report the failure rather than proceeding.

### 4. Report

Print the project location, the entry namespace, and next-step commands:

```
Created Biff project at <path>.
Main namespace: <com.example>

Next steps:
  cd <project-dir>
  clj -M:dev dev          # Start the app on localhost:8080
  clj -M:dev --help       # List dev tasks
  open http://localhost:8080

Edit src/<namespace_path>/app.clj to modify routes.
Edit src/<namespace_path>/schema.clj to modify the data model.
Read dev/repl.clj for REPL-driven workflow notes.
```

## Gotchas

- **The starter is interactive.** Do not pipe input unless you have already collected the namespace and project directory from the user.
- **`config.env` is gitignored.** It is generated by `clj -M:dev dev` (or `clj -M:dev generate-config`). Fresh clones must run one of those before the app will boot.
- **Generated CSS lives under `target/`.** The Tailwind file rebuilds on each save while `clj -M:dev dev` runs.
- **Namespace and directory naming.** The main namespace uses hyphens (`com.my-app`); the corresponding directory path uses underscores (`src/com/my_app/`). The scaffolder handles this automatically; do not rename either by hand.
